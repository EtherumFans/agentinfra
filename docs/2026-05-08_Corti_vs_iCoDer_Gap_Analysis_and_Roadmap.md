# Corti vs iCoDer 全面差距分析与三阶段研发计划

> **日期**: 2026-05-08
> **范围**: 全栈对比（前端 24 页、后端 75+ 端点、Web Components、SDK）
> **目标市场**: 中国（医院 HIS/EMR 集成、ICD-10-CN/ICD-9-CM-3 编码、医保 DRG/DIP）

---

## 一、总体评估

| 维度 | iCoDer 当前 | 整体完成度 |
|------|-----------|-----------|
| 前端页面 | 24 页 | 55-60% |
| 后端 API | 75+ REST + 2 WebSocket | 60-65% |
| 数据库模型 | 17 个 | 70% |
| 智能体管道 | 8 步固定管道 | 60% |
| 嵌入组件 | 2 个 Lit Web Components | 40% |
| TypeScript SDK | 1 个完整客户端 | 65% |

---

## 二、架构层差距

| 维度 | Corti | iCoDer | 严重度 |
|------|-------|--------|--------|
| **前端框架** | Next.js / React | React 18 + Vite 5 | 🟢 持平 |
| **后端框架** | 微服务架构 (Go/Node) | FastAPI 单体 | 🟡 无水平扩展 |
| **数据库** | PostgreSQL + Redis + 向量数据库 | SQLite (嵌入式) | 🔴 严重 |
| **实时通信** | WebSocket + WebRTC | WebSocket (仅 STT) | 🔴 无 WebRTC |
| **认证** | OAuth 2.0 + SAML + SSO | JWT + OAuth 2.0 M2M | 🟡 无企业 SSO |
| **部署** | Kubernetes 集群 | Docker Compose 单机 | 🟡 无自动扩缩容 |
| **可观测性** | OpenTelemetry + Grafana | Python logging | 🔴 无结构化监控 |

## 五、差距汇总

### 🔴 严重缺失 (8 项) — 影响产品可用性

1. **数据库**: SQLite → PostgreSQL（不支持生产并发）
2. **编码词典数据**: 28+15 条演示 → 完整 ICD-10-CN/ICD-9-CM-3 词典（需 10 万+ 条，含医保编码）
3. **语音识别模型**: Whisper Tiny → Whisper Medium + 医学术语增强
4. **说话人分离**: 完全缺失（中国远程问诊核心功能）
5. **实时事实提取**: 前端正则无法替代 LLM 提取
6. **FHIR/HL7 标准输出**: 无互操作能力（中国互联互通测评必需）
7. **异步编码管道**: 同步阻塞式，无进度推送
8. **安全护栏可配置化**: 前端不能实际调整护栏规则

### 🟡 中等差距 (10 项) — 影响竞争力

9. **SSO/企业认证**: 缺失 SAML/OIDC（中国医院统一认证需求）
10. **文件上传**: 不支持 PDF/Word/图片
11. **DRG/DIP 可视化**: 后端有，前端未展示（中国市场刚需）
12. **编码对比**: 原始 vs AI 对比未实现
13. **AI 替代推荐**: 拒绝编码时无推荐方案
14. **实时编码建议**: 语音→编码端到端缺失
15. **临床文书模板**: 11 vs 50+，无智能填充
16. **可观测性**: 无结构化监控（无 Prometheus/Grafana）
17. **批量操作**: 批量编码、批量导入金标准
18. **多语言 STT**: 仅中英，中国少数民族语言/方言缺失

### 🟢 微小差距 (8 项) — 可快速补齐

19. **首页图表**: 真实数据替换随机模拟
20. **流式输出前端集成**: 后端 SSE Manager 已实现
21. **记忆系统前端接入**: 后端 MemoryExpert 已实现
22. **A2A 多智能体深度集成**: 后端已实现
23. **规则编辑器/测试器**: 提高编码规则管理效率
24. **树形编码浏览器**: 层级导航
25. **金标准从审核导入**: 一键升级
26. **评估维度拆分和趋势图**: 按科室/难度/时间
