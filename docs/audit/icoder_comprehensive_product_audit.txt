十四、执行顺序
严格按照以下顺序执行：
Audit Gate 0 — Git、工作区和证据基线
→ Audit Gate 1 — 仓库结构和启动复现
→ Audit Gate 2 — 产品页面和路由全量清点
→ Audit Gate 3 — 全页面浏览器走查
→ Audit Gate 4 — Agent 能力和调用链审计
→ Audit Gate 5 — Medical Coding / CDI / DRG-DIP 专项审计
→ Audit Gate 6 — A2A、Runtime、Expert、Tool 架构审计
→ Audit Gate 7 — Run、Trace、Event、Usage 审计
→ Audit Gate 8 — Embedded、SDK、API Client、Partner App 审计
→ Audit Gate 9 — 认证、安全、PHI、多租户审计
→ Audit Gate 10 — 模型、数据和评测资产审计
→ Audit Gate 11 — 测试、性能、部署和文档审计
→ Audit Gate 12 — Corti 对标和战略产品审计
→ Audit Gate 13 — 商业化与医院试点成熟度审计
→ Audit Gate 14 — 问题分级、整改路线和最终裁决
每个 Gate 都必须先形成证据，再形成判断。
