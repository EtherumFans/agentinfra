# Corti 对标与开发环境状态（2026-08-13）

## 结论

当前项目已形成可重复运行的开发环境工程候选，但尚不能认定为“完整复刻 Corti”或“生产可上线”。

- Agent Hub 共发现 32 个 Agent Pack：26 个用户可见、非弃用 Pack 均可执行，且 `maturity=runnable`、`launch_candidate_ready=true`；2 个为隐藏弃用迁移别名；3 个为隐藏的 MedCodER 内部 Expert stage；其余 1 个为隐藏可执行内部引擎。
- 26 个用户可见 Agent 的 discovery 与动态 A2A 路由均可达，但所有 Pack 仍保持 `production_ready=false`。
- 最新原子 40 例远程端到端运行 `candidate_20260813_agenthub_sdk_atomic` 为 40/40 HTTP 成功且 40/40 查询数范围达标；全过程未加载 Torch/BGE/sentence-transformers，也未运行浏览器自动化，没有再次发生 Windows 访问冲突。
- 原子运行的安全/质量门禁为：完整病历过问 0/10、清晰缺口漏问 0/10、多维泄漏 0、无证据查询率 0、诱导问题率 0、证据逐字锚定率 100%、4 个以上选项率 100%、逃生选项率 100%。
- 原始全样本与 Corti 的查询数差不超过 1 一致率为 0.60，平均绝对查询数差为 1.18，仍未达到冻结目标 0.80 和 0.50；但只统计 Corti 自身也落在预期安全范围的 20 例时，一致率为 0.90、平均差为 0.45。
- 对安全条件样本中的 GAP-006 进行增量整改后，独立真实 E2E 输出由 1 条变为 2 条安全单轴问句；该例与 Corti 的差从 2 降至 1。按增量证据推算，安全条件子集可到 0.95/0.40，但这不是新的原子 40 例结果，不能替代全量复跑。

## 本轮开发环境完成项

1. CDI 查询门禁闭环
   - 多 EvidenceSpan 持久化、API、前端展示和迁移。
   - 所有门禁丢弃均保留结构化审计工作项。
   - 复合问题限定为一次、最多 8 条、单轴改写，并重新进入必要性、资格、证据、语义与非诱导门禁。
   - 6 个以上选项和开放问题尾部冗余“是否”句式可做受限机械修复，修复后重新检查全部 NLQ 规则。

2. 确定性核心缺口覆盖
   - 左右侧别跨文档冲突。
   - AECOPD 异常血气对应呼吸衰竭类型。
   - 未分型肺炎的临床类型。
   - 糖尿病酮症酸中毒核心诊断。
   - 胆总管扩张、胆汁淤积指标异常对应胆道梗阻相关诊断。
   - 胆源性/特发性胰腺炎跨文档病因冲突。
   - 病程记录合并症未进入出院诊断的完整性问题。
   - 小细胞性贫血、低铁蛋白与便潜血阳性时，分别保留“贫血类型”和“缺铁性贫血与慢性消化道失血诊断关系”两个单轴问句；出血来源、检查建议、严重程度和孤立检验意义草稿只进入审计队列，不发送给医生。

3. 中国临床文本安全适配
   - PHI 姓名规则保护常见临床短语，避免将“左/右肋骨”“双肺清晰”“窦性心律”“ST 段抬高”等误删。
   - 仍可识别并脱敏“患者张三”“姓名：张三”等真实姓名形态。
   - 稀疏症状记录、随访/检查计划、孤立检验解释、已明确数值和病程不再被误当成诊断型 CDI 缺口。

4. 运行稳定性
   - 语义和断言审查由并发改为串行，避免单病例连接峰值。
   - 两次完整 40 例运行分别耗时 841.7 秒与 852.6 秒，HTTP 成功率均为 100%。
   - 后端工作集观测范围约 37–211 MB，期间回落明显，没有持续内存增长模式。

## 与 Corti 的剩余能力差距

### Agent Hub 真实示例回归（本轮新增）

- 对 26 个用户可见 Agent 逐一使用各自 Pack 的 `example_inputs`，经统一 `POST /api/v1/agents/{agent_id}/run` 串行执行；结果为 **26/26 通过**。
- 每例均检查 HTTP 契约、运行态、provider completion、工具调用无错误、`run_id`/`trace_id`、Pack 必填字段、结构化投影、强制人工复核、生产写回阻断、高风险内容安全和临床数量溯源。数量门禁只接受输入/成功工具中的原值、由输入时间戳可复算的时长，以及同一数值范围内可证明的单位继承；未提供的独立临床阈值会失败关闭。权威结果见 `backend/reports/agent_hub/examples_e2e_20260813/agent_hub_examples_e2e.json`。
- 这证明 26 个 Hub Agent 已从 metadata/smoke 状态收敛为开发环境中的可运行、可审计、可测试上线候选；不代表完成临床有效性、生产可靠性或监管批准。
- 本机为避免已确认的 Torch/PyArrow 原生崩溃，语义 BGE 检索保持禁用；`search_icd` 在精确目录术语/编码命中时改用 37,897 项只读 ICD-10-CN 词法 fallback，并明确记录 `lexical_catalog_fallback` 来源。加严后的门禁会拒绝 `finish_state=incomplete` 或 mandatory tool 未完成；诊断提取示例现为 `finish_state=completed`。该精确 fallback 仍不等同于 Corti 的完整托管语义检索。
- 26 个 Pack 虽都有输入示例，但仅 11 个有期望输出、仅 5 个覆盖全部必填字段。现阶段用可审计的安全/契约断言替代伪造模型“标准答案”；临床内容金标准仍需独立专家标注。

## Windows 崩溃判断

事件日志只显示 `0xc0000005`，但本机 Minidump 的标准 ExceptionStream 已给出具体操作：2026-08-13 05:25:32 的 `pyarrow\arrow.dll` 为写访问冲突（目标地址 `0x66F`），同一 Python 进程在 05:25:44 再次于 `arrow.dll` 发生读空地址冲突（目标地址 `0x0`）；2026-08-10 的 `torch_cpu.dll` 为读访问冲突（目标地址 `0x2DC79A60`）。所以“不可读”和“不可写”都实际发生过，至少涉及 PyArrow 与 Torch 两个原生扩展，不能归因为单一模块，更没有证据归因给 Clash Verge。`codex.exe` 的 `0xc0000409` 和 ChatGPT 的 `RADAR_PRE_LEAK_64` 是另外两类记录。本轮持续避免加载这些高风险原生数据/模型栈，串行后端测试未复现崩溃。
