# iCoDer CCL 2026 本地监督 OOF 基线阶段总结（2026-08-27）

## 阶段结论

在用户明确授权的 `E:\iCoDerA\data` 范围内，iCoDer 已完成一个不依赖 Torch、sentence-transformers、PyArrow 或外部 Provider 的中国临床编码监督开发基线。它以完整 1,800 例治理 fixture 做确定性、按主诊断分层的五折 out-of-fold（OOF）预测；每例只由未见过该例及相同文本摘要的训练折预测。

权威第三次 wrapper 运行结果：主诊断精确率 **89.56%**、全诊断 micro F1 **50.79%**、有主手术 gold 病例的主手术精确率 **66.38%**、全手术 micro F1 **83.80%**、完整诊断+手术集合精确匹配 **1.72%**。这相对无监督目录精确名称下界分别提升 **80.50、28.30、50.27、67.53、1.72 个百分点**。

这是同一训练工作簿上的开发 OOF，不是未触碰的外部测试集、独立临床 gold、Corti 同病例 head-to-head、医院验收或生产准确率。完整集合精确匹配仍只有 1.72%，尤其多诊断完整性仍明显不足，因此不能把高主诊断/手术聚合指标解释成完整临床编码能力。

## 工程实现

1. 新增 `bounded-char-ngram-neighbor-v1`：
   - 仅用病历 `text` 生成每文档最多 2,048 个稳定哈希二/三字符特征；
   - 过滤过稀或过常见特征，以有界倒排索引检索最多 19 个训练邻居；
   - 使用加权投票生成主诊断、多诊断、主手术与其他手术候选；
   - 所有输出代码必须属于完整性已验证的 39,756/28,394 中国运行目录，否则整轮失败。
2. 五折分配按主诊断分层并由固定 seed + 文本摘要确定；相同文本强制进入同一折，标签冲突或任一标签不能覆盖全部折时失败。
3. `EvaluationInput` 只携带文本摘要和有界特征，不包含 gold 字段；预测字典也不携带病例摘要或 gold 派生 digest。
4. 不写病例级 prediction packet、模型文件、邻居、错误样本或特征；仅输出 4 KB 左右的聚合 JSON。
5. 持久报告有 canonical SHA-256；篡改、乐观 claim、病例级字段、目录外代码、自身训练暴露或数据绑定漂移均失败关闭。
6. Release runner 在执行前重新校验授权工作簿 SHA-256 与治理审计，清空 LLM 凭据，执行后验证聚合字段与受保护数据库哈希。

## Runtime 与上线边界

- 本阶段不把 CCL fixture 或由其训练的持久模型装入 Agent Runtime。用户对本机使用的授权不等于可再分发、云部署、外部处理或医院生产授权。
- `Medical Coding`、`Principal Diagnosis Review` 等 Agent 可以把该结果登记为“本地监督开发基线已测量”，但不得因此将 `production_ready`、独立临床 gold、Corti parity 或租户模型就绪提升为通过。
- 要进入 Runtime，仍需组织级训练数据 manifest、许可/用途/地域/保留期、独立去标识证明、训练/验证分离、模型版本与回滚、推理输入安全、真实医院外部测试集和人工 reviewer。
- Windows BGE/PyArrow 原生安全门保持不变；本基线绕开危险依赖，不代表这些依赖已经修复。
- 授权工作簿只读，未复制到新位置；没有网络、LLM Key、Corti credits 或外部数据传输。
