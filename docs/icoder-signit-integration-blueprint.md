# iCoDer × 易企签 — 全功能整合蓝图

## 两产品能力矩阵

| | iCoDer | 易企签 |
|---|--------|--------|
| 核心 | AI 编码审核 + 智能体编排 | CA 可信签署 + 无纸化归档 |
| 角色 | 编码员、医保办、质控科 | 全院临床科室、医务处、病案室、患者 |
| 输出 | 编码审核报告、DRG 分组 | 经 CA 签名的 PDF/OFD 版式文件 |
| 合规 | 编码规则引擎 + 审计链 | CA 时间戳 + 证据保全 + 人脸识别 |

## 一、10 个整合切入点

### 1. 可信身份认证 — CA 证书作为 iCoDer 的登录凭证

```
易企签 医师 CA 数字证书
    ↓
iCoDer 登录认证
    ↓
医师扫码登录 iCoDer → 自动加载个人 CA 证书
    ↓
所有编码操作自动绑定医师身份
```

**价值:** 直接解决 iCoDer 当前无 SSO 的问题，同时为后续签名链路提供身份基础。

### 2. 编码审核报告 — 三级签名+归档

```
iCoDer 编码审核完成
    ↓
自动提交至 易企签 签署平台
    ↓
签署链: 主治医师签名 → 编码员签名 → 科主任签名
    ↓ (每步加盖时间戳)
签署完成 → 归档为 PDF/OFD 版式文件
    ↓
归档文件 URL 回写到 iCoDer 审核记录
```

**价值:** iCoDer 的产出首次具备法律效力，可直接作为医保结算凭证。

### 3. 编码及时率监控 — 签署时间 + 编码完成时间联动

```
易企签 签署及时率统计
    ↓ 关联
iCoDer 编码完成时间戳
    ↓ 形成
签署时效性看板
    ├─ 入院24小时内完成编码签署? 
    ├─ 手术记录术后48小时内编码?
    └─ 医保结算清单出院前签署完成?
```

**价值:** 直接满足《医疗质量安全核心制度要点》中对文书签署及时性的监控要求。电子病历 5 级评测的核心得分项。

### 4. 病案首页质控 + 可信归档

```
iCoDer 首页质控（规则库 32 套）
    ↓ 检查通过
易企签 首页审核签署（主治 + 编码员 + 病案医生）
    ↓ 签署完成
易企签 归档（版式文件 + 结构化数据）
    ↓
iCoDer 可继续查询该首页的编码历史 + 签署状态
```

**价值:** 把 iCoDer 的质控能力从"发现问题"升级为"发现问题→修复→签署→归档"的闭环。易企签已有的 1 套《医保结算清单质控规则库》和 1 套《住院病案首页质控规则库》可以直接与 iCoDer 的 32 套规则叠加使用。

### 5. 手术知情同意书 — 与手术编码关联

```
术前
    易企签: 患者签署《经皮椎体后凸成形术知情同意书》
          ↓ 采集身份证 + 指纹 + 人脸 + 音视频
术中医嘱
    HIS 系统记录手术操作
术后
    iCoDer: 提取手术事实 → 分配编码 (81.6600x001)
    易企签: 手术记录 + 手术编码报告 → 医生签名
          ↓
    知情书 + 手术记录 + 编码报告 → 一体化归档
```

**价值:** 医保核查时可同时调出手术编码依据、签署知情书、术中记录，形成完整的合规链条。

### 6. 患者主索引关联 — 以患者为维度查询全流程编码与签署

```
患者 ID: P20260001
    ├─ 入院记录 ── iCoDer 编码 [I21.100, I10.x02] ── 易企签 签署 [主治 ✓]
    ├─ 手术记录 ── iCoDer 编码 [00.6600x002] ── 易企签 签署 [手术医生 ✓]
    ├─ 知情同意书 ── 易企签 签署 [患者 ✓, 家属 ✓]
    ├─ 出院小结 ── iCoDer 生成 ── 易企签 签署 [主治 ✓]
    └─ 病案首页 ── iCoDer DRG [FM19] ── 易企签 签署 [编码员 ✓, 科主任 ✓]
```

**价值:** 易企签的"基于患者主索引的精确检索"功能 + iCoDer 的编码报告关联，让每个患者的全流程文书、编码、签署状态在同一个界面查询。

### 7. 单机设备报告 + 编码

```
心电/超声/病理 单机设备
    ↓
易企签 虚拟打印 + 结构化分析（AI 识别患者、检查项目、指标）
    ↓
结构化数据传入 iCoDer
    ↓
iCoDer 多源证据融合（文本 + LIS + PACS + 单机设备报告）
    ↓
编码候选更精准
```

**价值:** 易企签已经解决了单机设备的数据采集和结构化问题，这正是 iCoDer 多源证据融合需要的最后一类数据源。

### 8. 业务可视化大屏

```
易企签 业务大屏
    ├─ 签署量统计（按科室/按日期）
    ├─ 签署及时率
    └─ 设备运行状态

    ↓ 嵌入 iCoDer 首页

iCoDer 运营大屏
    ├─ 编码审核量（按科室/按日期）
    ├─ 编码准确率趋势
    ├─ DRG 入组率
    ├─ 签署完成率 ← 来自易企签
    └─ 签署及时率 ← 来自易企签
```

**价值:** 给医院管理者一个统一的视角：编码质量 + 签署合规 = 医保申报准备就绪。

### 9. 知情文书模板 + 编码绑定

```
易企签 知情E文书系统
    ├─ 全院统一知情文书模板管理
    └─ 每种模板绑定对应的 ICD-9-CM-3 / ICD-10 编码范围

iCoDer 编码结果
    ↓
自动匹配需要签署的知情文书模板
    ↓
推送至 易企签 签署终端
    ↓
患者/家属完成签署
```

**价值:** 让"手术编码"与"知情同意书"自动关联，避免编码与文书不一致的合规风险。

### 10. 证据保全 + 编码审计链

```
iCoDer AuditTrailExpert
    每一步编码决策 → 时间戳 + 证据 + 操作人
    ↓
易企签 时间戳服务器
    每一步加盖 CA 时间戳
    ↓
易企签 存证出证
    完整的证据保全链，符合《电子签名法》要求
    ↓
医保飞检/司法取证时
    一键导出完整的编码→签名→时间戳证据链
```

**价值:** 这是两个产品 1+1>2 的核心场景。iCoDer 有编码证据，易企签有法律效力，组合起来就是不可抵赖的完整审计链。
