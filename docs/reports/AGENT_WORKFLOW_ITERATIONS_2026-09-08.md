# 评测发布、可视化输入与历史检索迭代

三项实现完成，2026-09-08 在隔离环境验收。未部署生产环境，未改变数据库版本（仍为 083）。

## 1. 评测与发布联动

- 评测绑定草稿定义、解析后的运行配置、外部依赖登记摘要及用途。提示词、解析配置或依赖变化后，原报告不再满足门槛。
- 发布页面可以为当前用途启用强制评测。后端检查同一摘要、同一用途的最新报告，只有一致且全部检查通过才允许发布；最新失败报告不能被较早的通过报告覆盖。
- 未配置策略时保持提示模式，以兼容已有调用。配置字段为 `config.release_evaluation_required_for`，支持用途数组及 `*`；支持质量改进、研究、诊疗、支付、医疗运营和公共卫生。该设置管理发布检查，不替代运行时用途授权。
- `POST /api/rest/v1/agent_definitions/{id}/publish?purpose=quality_improvement` 发布指定用途；缺省为质量改进，旧 `/version` 别名也执行同一检查。
- 发布快照保存关联评测标识、用途和摘要。执行时内部评测元数据不进入运行配置。
- 允许不选基线，只检查候选草稿，支持首次发布或原基线依赖已变化的情形。历史报告缺少新的绑定字段时必须重新评测才能满足强制门槛。
- 这属于软件检查，不能代替专业人员制定金标准或业务质量审批。

## 2. 可视化输入

- 评测支持增删样例、正文、包含/排除短语、字段路径及文本/数字/布尔/空值检查。
- 批量任务支持增删文书；表单与高级 JSON 共用数据，切换保留输入。
- 评测导入 JSON；批量文书导入 JSON 或单份 TXT。导入上限 1 MB，无效文件保留已有输入。
- 提交前逐条校验空正文、长度、重复样例标识、缺失检查和批量上限。后端原有验证继续生效。
- 沿用提交幂等标识：不确定结果下重试同一资料不会重复入队，资料变化才生成新标识。

## 3. 历史分页检索

- 任务、评测、依赖支持 `limit`（1–100）、`offset` 和 `q`，前端每页 20 条；响应提供 `has_more`。
- 任务按任务标识或版本搜索，可按状态筛选，范围保持当前组织和当前调用者。
- 评测按报告标识、候选版本或样例摘要搜索；`paginated=true` 返回分页对象，省略时保留原数组响应形状。
- 依赖按名称或版本搜索；`current_only=true` 仅查询当前登记版本，草稿绑定选择跨页保留。历史与绑定选择分别分页。
- 排序使用创建时间和唯一标识，解决同时间记录顺序不稳定。搜索中的 `%`、`_` 按字面处理。
- 当前为 offset 分页；持续新增记录时应返回首页刷新，不提供冻结快照或全量导出语义。
