# 文书结果复核闭环验收

本轮交付文书生成页面的人工复核首版。医学编码优化继续暂停。

## 使用流程

生成文书后，点击“保存并开始复核”，明确保存本次原文与初稿；随后对照原文逐段接受、修改或驳回。修改、驳回必须填写原因。全部段落处理完且至少保留一段后，可以完成复核并确认。确认后锁定内容，导出人工确认稿；驳回段落不进入确认稿，但原文和处理记录继续保留。

“已保存的复核记录”支持分页回看。导出初稿与确认稿均为 TXT，标注稿件性质、记录标识和版本，确认稿另含确认人、确认时间。

## 数据与权限

- PostgreSQL 迁移 090 新建 document_reviews；本地 UI 与隔离测试数据库均完成迁移。
- 原文、初稿、处理意见、修改前后文本和确认信息使用 EncryptedPHIJSON 加密。组织 RLS 强制开启。
- 组织成员可复核，viewer 只读。版本检查拒绝过期修改，已确认记录禁止修改。
- 保存使用幂等标识；API 不提供删除或修改历史记录的入口。
- 保存的是工作台提交快照，来源标记为 workbench_submitted_snapshot，不宣称与服务端模型运行有不可伪造的关联。
- 原文查找仅为逐字匹配辅助定位，不自动判断临床事实是否成立。

## 验证

- 隔离 PostgreSQL：2 项集成场景通过，覆盖完整流程、幂等、跨组织访问、只读权限、过期版本冲突、全驳回禁止确认、导出限制及数据库密文检查。
- 前端：3 个测试文件、10 项测试通过；TypeScript 检查通过。
- Vite 生产构建通过，仍有已有的大包体积与动态/静态混合导入提示。
- 实际浏览器：以显式标记的合成文书保存两段初稿，修改第一段、驳回第二段、完成确认；回到正式文书页面，重新打开已确认 v4 记录，确认编辑控件锁定、导出入口启用。
- 修复新复核面板加入后工作区压缩重叠问题，并再次执行前端回归与类型检查。
- 本地后端就绪检查及前端 API 代理检查通过。

本轮没有调用真实模型。浏览器验证使用合成文书；导出正文保留/排除规则由 PostgreSQL 集成测试验证。当前范围为文书复核，尚未将此界面推广到编码与质控智能体结果，也不包含医院系统回写或多级审批。
