## Critical findings (CONFIRMED)

### 1. NO "Calling expert: coding-expert" message (vs Code Validation Probe 1)

Code Validation Probe 1 SSE contained:
```
data: {"data":{"message":"Calling expert: coding-expert","state":"working"},"type":"data-status-update"}
```

Compliance Guardrail Probe 1 SSE has **NO** such message. The agent recognized the empty `{{COMPLIANCE_RULESET}}` placeholder and refused BEFORE delegating to coding-expert.

**Inference (CONFIRMED):** The LLM orchestrator short-circuits on the ruleset precondition. No tool calls fired. No expert delegation. This is a **LLM-driven control flow decision**, not a rule-engine gate.

### 2. state: "input-required" (NEW — not seen in Code Validation Probe 1)

Code Validation Probe 1 ended with `state: "completed"`.
Compliance Guardrail Probe 1 ended with `state: "input-required"`.

**Inference (CONFIRMED):** Corti's task state machine has at least 3 terminal states:
- `completed` — task finished normally with output
- `input-required` — agent needs user to provide additional input/configuration
- `failed` (presumed — not yet observed)

**Diff vs iCoDer:** iCoDer's task state machine (`TaskState` in `app/icoder/agent_runtime/orchestrator/inbound_handler.py`) has `received / planning / delegating / aggregating / completed / failed`. **iCoDer has NO `input-required` state** — this is a Phase 3-D2.5 gap (D5 family).

### 3. Refusal message is LLM-generated, NOT a fixed template

System prompt prescribes:
> "Compliance ruleset not configured. This agent requires an active {{COMPLIANCE_RULESET}} before evaluation can begin. Please configure the ruleset and resubmit."

Actual agent response:
> "Compliance ruleset not configured. This agent requires an active {{COMPLIANCE_RULESET}} before evaluation can begin. Please configure the ruleset (**e.g., CCI edits, payer policy, LCD, or internal rules**) and resubmit this code set for evaluation."

The LLM added **"e.g., CCI edits, payer policy, LCD, or internal rules"** — pulled from the system prompt's examples list. The LLM also added **"this code set"** before "for evaluation."

**Inference (CONFIRMED):** Compliance Guardrail Agent is LLM-driven, NOT a fixed template rule. The LLM:
- Read the system prompt
- Recognized the empty `{{COMPLIANCE_RULESET}}` placeholder
- Generated a refusal message drawing on context from the prompt's examples
- Produced slightly varied phrasing across runs (would need Probe 1 re-run to confirm variation, but the addition of "e.g., ..." strongly indicates generation, not lookup)
