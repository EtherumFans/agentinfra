## 安全提交拆分顺序

1. **Baseline hygiene**：本工具、测试、忽略规则、本报告和清理删除项。
2. **Backend schema/security**：迁移、认证、租户、PHI、审计与对应测试。
3. **Runtime/Agent Hub**：A2A、MCP、Agent packs、runtime 和契约测试。
4. **Clinical capabilities**：CDI、Medical Coding、STT、模型治理与受控证据。
5. **Frontend**：页面、服务、类型和前端契约测试。
6. **SDKs**：JavaScript、Python、.NET，随后在三工具链 CI 构建。
7. **Canonical evidence**：只提交被最终报告引用的最小证据集；中间运行输出删除或转存制品库。

禁止使用 `git add -A`。每个提交应使用明确路径列表，并在提交后从干净 checkout 重放对应验证。

## 退出条件

可信不可变基线尚需满足：

- 后端依赖环境可复现并通过 PR gate；
- .NET SDK 在支持环境完成构建和测试；
- canonical evidence 引用闭合，未引用的海量中间报告被清理或迁出 Git；
- 上述提交拆分完成；
- `git status` clean；
- 在 clean checkout 重新生成清单和 release candidate manifest；
- 创建本地 annotated tag（不自动 push）。
