# P1 审计签名链与不可变归档增量

## 范围与结论

revision 070 在 Wave 5 revision 069 之后增加 `audit_integrity_archive`。每个租户及
系统审计分区分别形成连续链；归档保存规范化审计载荷、载荷哈希、前序哈希、链哈希、
签名算法和密钥版本。PostgreSQL 通过事务级 advisory lock 串行化同一分区的追加，唯一
约束阻止重复序号，触发器无条件拒绝 UPDATE/DELETE。

生产 PostgreSQL 的 `log_action()`、`system_audit()` 和
`tenant_owned_system_audit()` 在原审计写入的同一事务中追加签名归档。任一步失败都会令
业务事务回滚，避免产生“有审计、无完整性证明”的静默缺口。SQLite 仅作为本地开发与
单元测试存储，不宣称提供不可变保证。

## 安全边界

- 普通租户只能读取当前数据库租户上下文对应的归档，不能直接写入归档表。
- 安全定义追加函数核对源审计存在性、组织归属、系统分类、链头、摘要格式与序号。
- 系统分区使用独立 `system` 链，租户链之间互不泄露事件内容。
- 热审计表可以按既有保留策略清理；归档故意不使用 `audit_log_id` 外键，因此证明不会
  随热数据删除。
- 离线验证器会检测载荷修改、重排、缺失、前序哈希断裂、错误密钥版本和签名失败。

## 密钥与归档成熟度声明

当前签名器提供可替换接口及 HMAC-SHA256 实现。云模式必须显式注入
`ICODER_AUDIT_SIGNING_KEY` 与稳定的 `ICODER_AUDIT_SIGNING_KEY_ID`；本地模式才允许
从应用 secret 派生域隔离开发密钥。此机制提供真实的密码学完整性与轮换版本标识，但
不等同于已接入云 KMS 非导出密钥。

`audit_integrity_archive` 是数据库内 WORM 控制层，不等同于跨账户对象存储 Object
Lock。进入生产发布前仍需完成：KMS MAC/非对称签名适配、旧 key verifier registry、
按周期封存到启用合规保留的对象存储、legal hold、删除审批、外部时间戳/锚定、恢复后
全链验证和监管导出验证。
